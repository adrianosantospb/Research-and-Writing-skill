# Related Work

Rules: R11–R13, C6, I1, I4. Purpose: critically analyze previous research and position the contribution.

## Per-study analysis (the author's 4-part strategy)
For **each** relevant study, address all four parts. Use `assets/templates/related-work-card.md` to collect them first, then write prose.

1. **Study overview** — main purpose of the work and a concise synthesis.
2. **Main contributions** — what the original authors claim as their achievements (attribute: "the authors propose/report…").
3. **Relationship to the proposed work** — similarities in objectives, methodology, technologies and application domain.
4. **Technical gaps and limitations** — problems not addressed, limitations of the approach, aspects the proposal considers that this study did not.

## Synthesis
- Group studies by theme/approach when there are many; still keep the 4 parts traceable for each.
- Close by stating clearly the gap the proposal fills (R12).

## Comparative analysis table (R13)
- Rows: related works. **Last row: the proposed approach** (bold or highlighted).
- Columns: evaluation criteria, technical characteristics, limitations, supported features — chosen from the gaps identified above.
- Use consistent markers (✓ / ✗ / ◐ partial, or Yes/No/Partial) and explain them in the caption.
- Cite every row. The proposal row must match what the Method actually delivers (C6).
- Template: `assets/templates/comparative-table.md`.

## Rules for sources
- Only include studies the author provided or that you retrieved and verified. Never fabricate a paper to fill a row (I1).
- If you have only an abstract, say so in the card ("analysis based on abstract only").

## Common mistakes
- A list of summaries ("X did A. Y did B.") with no relationship or gap.
- Criticizing studies for not doing what they never intended — frame gaps relative to *your* problem.
- Table whose criteria were chosen so only the proposal wins without justification.
